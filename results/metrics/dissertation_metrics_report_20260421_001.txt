====================================================================================================
                              METRIC CALCULATION METHODOLOGY & FORMULAS                             
====================================================================================================

  1. Visibility Coverage (%)
     Formula: (Total Steps Detected / Total Steps Attempted) * 100
     Definition: Measures the security stack's ability to provide end-to-end auditability
     across the entire kill-chain.

  2. Mean/Median Time to Detect (MTTD)
     Formula (Mean): Σ(Detection_Timestamp - Attack_Timestamp) / N_Detected
     Definition: Quantifies the responsiveness of the SIEM pipeline. Median is used to
     offset outliers caused by network batching or log ingestion delays (e.g., Suricata).

  3. True Positives (TP)
     Definition: Security alerts matching known attack signatures that occur within a
     [-60s, +300s] time window of a logged attack step execution.

  4. False Positives (FP)
     Definition: Security alerts from tracked rules that occur outside the valid attack
     windows. This measures the 'noise' or 'alarm fatigue' generated by the system.

  5. Detection Precision
     Formula: TP / (TP + FP)
     Evaluation: 100% Precision indicate that the Zero-Trust correlation rules are
     highly specific and only fire in response to verified malicious activity.

  6. Scientific Window Correlation (Test Horizon)
     Logic: All SIEM alerts occurring before the 'Test Start' (T_first_step - 60s) are
     mathematically discarded to prevent historical noise from skewing live metrics.

  7. Nmap Step Coverage — Shared Alert Behaviour
     Note: Suricata fires rule 1000041 (Wazuh 100035) at most once per 60-second interval
     per source IP, regardless of how many Nmap scan steps execute within that window.
     As a result, the same Wazuh alert may match all four Scenario A Nmap steps. This is
     intentional: the SIEM correctly identifies the sustained reconnaissance event as one
     security incident. Each step is reported individually for narrative fidelity; the
     shared match is a property of Suricata rate-limiting, not a metric inflation artefact.

  8. Detection Sensitivity (Recall) — Methodology Note
     Formula: Sensitivity = TP / (TP + FN)
     Limitation: This engine does not track False Negatives (FN) because FN detection
     requires a complete ground-truth manifest of every alert that should have fired.
     Expected detection rules per scenario:
       Scenario A — 100035, 100029, 100028, 100031, 100041
       Scenario B — 100101, 100103, 100501, 100210, 100060, 100025, 100026, 100027
       Scenario C — 100502, 100520, 100521, 100532
     A future extension may compare this manifest against ingested alerts to produce
     an explicit sensitivity score.
